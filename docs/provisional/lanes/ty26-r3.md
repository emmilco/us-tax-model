## What changed

- `tools/year_changes.py`
  - New kinds on the ambiguity register (`ambiguities/<year>.yaml`, by entry id): `add_ambiguity {entry, after?}`,
    `set_ambiguity {id, field, from, to}` and `remove_ambiguity {id}`. Each fails as the line kinds do (gone, stale,
    already applied, collision, malformed: a missing register field or a set of `id`).
  - After the operations, the register checks the build's rules (`engine/src/check.ts`): every line's `ambiguity`
    names an entry (dangling), no line or interview file names a removed entry, an added entry is linked or carries
    `unlinked`, and an entry whose last linking line goes (removed, or its link set away) is removed or given an
    `unlinked` reason. The register is read from the year's register file (`Tree` takes it) and written entry by entry
    at adoption (`write_state`).
  - `add_question` takes `default` and `reason`. A new input line without them fails ("default: ... has no test-data
    default"), as does a value its type refuses (Bool; integer, non-negative unless Dollars; a value of its enum, an
    enum the from-year lacks being left to the parameter lane) or a reason that is not one line.
  - Split files: `load_changes` already keyed on the `form:` field (checked); files now apply grouped by the name's
    form part, the form's own `<form>.yaml` before its `<form>.<topic>.yaml` files. Plain sorted order put
    `fa.more.yaml` before `fa.yaml`, so a split file could not build on lines the form's own file adds.
  - `--self-test`: 19 new planted cases (three default failures, eleven register failures, a collision across two
    files) plus a split file that applies, and the write test now covers the register (data equal, untouched entries
    byte for byte).
- `tools/year_changes.py` writer (closes BUG-NEW-ty26-o2-01): a rewritten block loses its YAML anchors, so
  `rewrite_list` now also rewrites every kept block that aliases an anchor of a rewritten (or removed) block, with the
  alias expanded, until none is left. The dumper no longer emits anchors or aliases. A self-test case plants it: an
  anchored `refuses` on a line an operation changes, aliased by a kept line. Without the fix the written file fails to
  load ("found undefined alias"); with it, it loads and equals the applied data.
- `tools/fixtures_year.py`: `carry_defaults` adds each new input's default after its anchor's default and drops the

## Follow-on: operations on the interview files (BUG-NEW-ty26-o3a-01)

**Decision.** The owner delegated this, and the coordinator decided it: the check is not relaxed; instead, new operation kinds edit the interview files.

**New kinds in `tools/year_changes.py`.**
- The kinds:
  - `set_interview {file, field, from, to}`. With `list` and `item` added, it sets a field of the list entry that has that id.
  - `add_interview_item {file, list, item, after?}` and `remove_interview_item {file, list, item}`. The item is either an entry with an `id` (named by its id) or a plain value (a target, a ref).
  - `add_interview_file {file, data}` and `remove_interview_file {file}`.
- Files are named by their path under `interview/<year>/`. `questions.yaml` exposes `bank.groups` and the other bank keys, but not `bank.questions`.
- Failure modes are the same as for line operations: gone (with the closest names suggested), stale, already applied, collision, malformed. Two things are refused as malformed: setting a profile's `questions` or the bank's questions (the question operations own those), and removing a profile or the bank.

**Checks after the operations.**
- Anything an interview operation writes must name lines that exist.
- An entry id or mapping key that an operation removes must not still be named in its file. For example, a coverage set that a row still `uses`.
- Every tick-box group in the bank must be named by a question, and every question's `group` must be declared. This mirrors `engine/src/tick-groups.ts`, which the check did not cover before.
- The existing check for removed ids now reads the interview files as the operations leave them.

**The writer.**
- An entry of an id-keyed list (coverage rows, bank groups) gets its own block, via `rewrite_list`.
- A list of plain values is edited one item line at a time, so comments stay. A flow list (`refs: [..]`) stays on one line.
- Any other path is rewritten at its key.
- A removed file is deleted.
- The writer refuses (SystemExit) if a written file does not load as the applied data.

**Self-test.** It adds a coverage file, a gate-frequency file, a persona, a profile target list with a comment, and a bank group. It plants 12 failure cases, plus a test that the written files equal the applied data with comments kept. The self-test now has 56 cases, all as expected.
