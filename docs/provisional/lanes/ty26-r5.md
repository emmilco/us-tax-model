## What changed

- `tools/year_rehearse.sh` (new): copies the tree to a scratch directory outside the repository (refused inside it;
  one run per destination, by lock), then runs the adoption steps in the copy and logs each (`DEST/out/`,
  `summary.tsv`). The steps: build 2025, `--adopt`, stage the proposed parameters and tables, `citations.py --strict`,
  build and render 2026, rebuild 2025, `fixtures_year.py --no-hand-work`, `test-fixtures`, `year_carry.py` dry and
  `--write`, `review_store.py check`, `check_logs.py`, `rerun_all.py --dry-run`, a second dry run over the forms
  rerun_all leaves out, and a digest of the reports. It has labelled stand-ins for r5-01 and r5-02 (automatic, only
  on those exact failures) and `--stand-in-sources` (opt-in: unarchived documents taken from 2025). It also has
  `--reuse-build`, because each 2025 build took 46 to 59 minutes at load 90 to 270.
- Defects in the script itself, fixed in this lane: (1) pyenv picked another Python, one without yaml, outside the
  repository, so the Python is now pinned from the tree; (2) two runs could share one destination, so there is now a
  lock; (3) the unlogged-forms estimate was added after the full run. Its code was run by hand in the same copy;
  the script as committed was not rerun end to end after that addition.
- `tools/README.md`: one paragraph in "Year changes as operations".
- `bug_pending/ty26-r5-01` to `-07` (via `new_bug.py`). I corrected r5-03, r5-04 and r5-05 by hand after
  creating them, to make a count or a cause exact.
