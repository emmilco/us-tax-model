## Decisions

- **Ids kept through renumbering** (design doc section 2, spec 4.3). The result is that `f8959.line13` is printed 18
  and `f8959.line18` is printed 12, and `s2.line18` is printed 14. This is confusing to read, but it is what lets
  the operations apply and lets review carry follow the lines. Each entry's `note` states the mapping.
- **New line 18 id `s2.excess_contrib`.** It cannot be `s2.line18`, which is the kept id of line 14. A descriptive
  name also avoids another number-based id that would go stale.
- **The Form 5329 split is a contract with lane O2**, which owns `person`/`f5329`. Schedule 2 reads two new awaited
  per-person totals. One is `person.x_tax_early`: Form 5329 line 4 (and the refused Part II line 8), Schedule 2
  line 5. The other is `person.x_tax_excess`: line 49 and the other excess-contribution taxes, Schedule 2 line 18.
  Both are new, not a narrowed `person.x_tax`, so that adoption refuses until O2 deliberately writes them. A narrowed
  `x_tax` read by line 5, next to a separately added line-18 total, could double-count line 49 without any failure.
  If O2 chose other names, the mend is one `set` of `expr.field` per line. Once both exist, `person.x_tax` (and
  `f5329.tax`) is read by nothing. The scratch build reports exactly that as its only error ("no line reads this
  sum_over line"), so O2 must remove it or repurpose it.
- **s2.line17c's cite is left to C-PEOP-19** (W1, wording). That entry touches `s2.line17c`, and two lanes setting
  the same field would collide. This lane sets only its `printed`.
- **Labels of the new subtotals do not claim more than was checked.** 15 and 20 say which lines this tool figures.
  17d names `s2.other`, which was verified from its expression (household employment, W-2 box 12 marks).
