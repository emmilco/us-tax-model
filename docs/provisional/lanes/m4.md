## Tools (in `m4_work/`)

- `mut.mjs`: the mutation judgement of `engine/dist/mutate.js` for a subset of mutants (`--docs a,b,ny_*` by the
  first segment of the mutant's location, or `--ids FILE`), over `--jobs N` child processes; `--ny` for New York.
  It loads a copy of `mutate.js` (`engine/dist/_m4mutate.js`, ignored) that also exports `outcome`, `judgingCases`,
  `selectMutants` and the argument tables; the judgement is the tool's own. It prints the counts, the stale
  arguments about the subset (same tests as `staleEquivalences`) and every unexplained survivor. Checked against
  the full `mutate --ny`: the same 35 unexplained New York survivors and 7 stale arguments.
- `casegen.py`: writes mutation cases from a table; each row names a base case whose inputs state every input, the
  changes (None leaves an input unanswered), and the values predicted by hand; it stops on any prediction the
  evaluator does not give, and takes a refusal's or unknown's record from the evaluator only after checking its
  gate or input is the one predicted. `gen_<form>.py` hold the tables. `ev.mjs` evaluates; `digest.mjs` prints
  `premiseDigest` of a premise list; `show.py` prints lines compactly with their readers.

Run outputs kept: `run_fed_0.txt`, `run_ny_0.txt` (start), `run_fed_2.txt`, `run_ny_2.txt` (after the cases and
arguments; `run_fed_2` predates withdrawing the asset case, so it shows that mutant killed). The final state is from the
full runs (see the end of this file).
