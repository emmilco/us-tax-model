## Changes

- `engine/src/mutate.ts`
  - **The sampled check (T-280).** Every keyed argument (`EQUIVALENT_IF`) that explains a survivor in a run is now
    checked by execution inside `mutate` (so inside check-all's full tier, steps `mutate` and `ny_mutate`). The mutant
    and the data are evaluated on 300 generated returns (seed 20261115; `MUTATE_SAMPLE` overrides the count) and the
    inputs of every fixture case, each as given and with answers withheld at rates 0.1, 0.3 and 0.6 (each answer at
    the rate, each roster, with its entries, at a quarter of it). Every line on a value sheet (not a `(helper)`) that
    reads the mutated line, directly or through other lines, gates or display conditions, must agree; the mutated line
    itself and helpers may differ (what T-280 described: "every line but the mutated one"; a helper is evaluated on
    every return also where no reader takes its value). A contradicted argument fails the run with the set, the line
    and both values. Arguments in `ANSWERED_ONLY` are held to the sets as given; on partial sets the first set that
    tells them apart is reported as a witness.
  - **Not vacuous.** Each argument reports how many sets *reach* the change (a line the mutant changes reads other
    operands or has another value) and *exercise* it (a value it can change differs). An argument no set reaches
    fails the run unless `UNEXERCISED_IF` states why with a condition the run checks. Two kinds need it, both New York:
    the 22 band-edge arguments (only a taxable amount of exactly edge + $1 differs; their own `holds` is arithmetic:
    whole-dollar bindings and both bands' tax computed at edge + $1) and the 2 MCTMT rate arguments (the rate
    multiplies line 54a/54b, the parameter `ny.zero` behind the MCTMT refusal gate; checked).
  - **Known-killed controls.** For each site (line, parameter or rate table) of a keyed argument, one mutant of the
    same site that a fixture kills is run through the same check; the run fails if none is rejected. A second pass
    on the controls compares every line of the return on the first 200 sets and fails the run if a line outside the
    compared readers differs (self-test of the restriction to readers).
  - **Cost control.** A line's readers receive only its value, so where every line the mutant changes first has
    exactly the same value (an unknown's details and its gate-pending mark included) its readers are not evaluated.
    Sites in a def are watched through the lines that read the def's instances. The check runs in the mutation
    workers (`mutate-worker.ts` takes a plan). `MUTATE_SAMPLE_TIMES=1` prints each site's time.
  - **Premise digest (coordinator's request).** A refusal entry now enters the digest as its gate line and
    `when_known` only, not its form, remedy or citation: their wording decides no route, and where an argument needs
    two refusals to be one value the sampled check compares the values. The digest self-test now plants a refusal
    form, remedy and citation change (digest unchanged; and on the real data, every refusal's prose reworded keeps
    every argument pinned) and a change to the order of refusal gates, a gate's line, a gate added or removed and
    `when_known` (digest moves). All digest literals were re-pinned mechanically:
    `docs/provisional/lanes/g1-t3_work/repin.mjs before` (old engine/dist) records each argument's premises and
    current digest; `after` (new engine/dist) replaces each literal that equalled the old digest. 66 literals; three
    arguments built in closures did not expose `premises` and now do (`eic.credit.line6.then0`, `roster_ok`,
    `s8812.line18a`), re-pinned by hand the same way.
  - Two arguments were already stale on this snapshot (`operand.sa.sa.gift_carryover_if_no_gifts.no.then1`,
    `operand.eic.eic.from_step1_income.no.then1`). I read each against the current lines (sa.line13's gates are
    `charity_limited_if_gifts` then `gift_carryover_if_no_gifts`; eic.clergy, line 10's gate `scope.schedule1` and
    the step1_income comparison are as argued; eic.clergy has gained a reader, f1040.line27b) and re-pinned them; the
    sampled check backs both. lmut is refreshing digests on the landing tree: at the merge take this lane's
    function and rerun `repin.mjs` (before on the merged tree's old dist, after on the new) rather than merging
    literals by hand.
- `fixtures/2025/mutation.json`: one new case (T-250, below), and (T-311) `f1040.withheld_other_any: false` stated in
  the 232 cases that lacked it
  (223 of them state `f1040.line25b: 0` and `line25c_other: 0`; false is the defaults table's value and agrees with
  those zeros). Lines 25b to 25d are now known in them. No existing expected value changed; `test-fixtures`: 2004/2004.
