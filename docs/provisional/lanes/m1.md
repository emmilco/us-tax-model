## How the runs were made

`mutate` has no option to limit a run to documents, so `m1_work/gen.sh` copies the built `engine/dist/mutate.js` to
`engine/dist/_m1_mutate.js` (build output, ignored by git) with a few exported helpers appended; nothing in the tracked
source changes. Rerun `m1_work/gen.sh` after every build or `tsc -p engine`.

- `node m1_work/run.mjs person,ira,...` — the mutation run limited to the mutants whose line is in the named forms,
  judged exactly as `mutate` judges them (`outcome`, then `equivalenceReason`), plus the staleness check of the
  arguments about those forms. Single-threaded; one process per form group.
- `node m1_work/check.mjs SPECS.json [INPUTS_OUT.json]` — for each candidate case (a base case from any federal
  fixture file with its defaults resolved, inputs set or removed, expected values, mutants to kill): the baseline
  value of each expected line, and for each named mutant which expected values change.
- `m1_work/line.py ID...` (a line's expression, refusal gates and readers, from `canonical/2025`),
  `pindiff.py`/`pinof.py` (what changed in a pinned argument's premises since the commit that recorded its digest),
  `repin.py ID [ADD,...]` (adds premises and records the current digest), `digest.mjs`.
- `m1_work/start_run.txt` is the first run on `fc6cdaf6`.
