## Open: operand.f1116.f1116.line35.line33 (line 35 reads line 32 instead of line 33)

Line 33 is the smaller of line 20 and line 32. When line 20 is a non-negative amount, line 32 (= line 24, which is
not more than line 21, which is not more than line 20) is never above it, so line 33 = line 32. They can differ only
when (a) line 20 is a refusal or unknown and line 18 is $0, so line 21 is $0 without reading line 20, or (b) line 20
is negative. For (a), line 35's refusal gates hide the difference on every input I could construct:
- with no foreign tax, other_category is true;
- with foreign tax and line 15 > line 18 = $0, us_loss is true;
- with line 15 <= $0, each withholding group's income after deductions is about $0, so any tax is high-taxed.

The only escape I found is a rounding window in which 4-place ratios rounded per column leave line 7 <= $0 while a
group's net income stays a few dollars above zero. That needs large deductions that roughly equal gross income, and
I did not construct it. A keyed argument would need (i) a proof that f1040.line16 is never negative, which means
pinning the whole tax-computation chain, and (ii) that rounding bound. I wrote neither. Recommendation: leave it
unexplained-open, or argue it with both premises after the owner decides it is worth pinning that many lines.
(`operand.f1116.f1116.line33.line20`, the analogous mutant on line 33 itself, is killed by
m1116_zero_taxable_other_tax, because line 33 is printed.)
