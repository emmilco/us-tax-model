# tax-formalization — Project Index

**Current execution order:** [temporary backlog plan](docs/2026-11-01_backlog_plan.md),
approved 2026-11-01; finish existing hardening before coverage expansion. The plan is a disposable
package tracker; `TASKS.md` remains the task register and `HANDOFF-NEXT-SESSION.md` the current handoff.
Earlier ordering statements below are historical where they conflict with this plan.

An open, verifiable formalization of the IRS forms-and-instructions layer for US federal individual income tax, plus a guided self-preparation interview tool as its first client. The user files their own return; the software never files, signs, or transmits.

Stages 0 to 21 are implemented (Stage 17, Schedule E, is next): the proof-of-concept return (Stages 0 to 5),
the integrity stack (Stage 7), dependents, head of household and Schedule 8812
(Stage 8), the earned income credit (9), retirement income (10), unemployment
compensation and the common Schedule 1 adjustments (11), the Schedule 1-A
deductions (12), married filing jointly (13), self-employment (14), other
credits (15), the remaining Schedule 1 items (16), the premium tax credit (18), the education credits (19), the
capital loss carryover (20) and Form 5329 (21). The estimate then read 82.2%; T-102 later counted filers
who can be claimed as a dependent, correcting it to 78.4%, so the first 80% goal remains open. A hardening phase
followed (`handoffs/HANDOFF-HARDENING-1.md`); see `HANDOFF-NEXT-SESSION.md` to continue. The product goal, coverage plan and verification regime are in
`spec/spec.md` sections 1, 2.4 and 6.5; the build order is in `spec/design.md`
section 5. No human line-by-line reading is claimed; see the trust statement in
spec 3 and its qualification. The integrity plan
(`docs/2026-10-22_integrity_plan.md`) precedes the remaining stages. The order of later stages follows the coverage estimate (spec 2.4, `reports/roadmap.html`).

## Naming conventions

- Workstream findings: `research/<nn>_<snake_case_workstream>.md`, numbered in the order of the project brief:
  - `01_prior_art_formalization.md`
  - `02_prior_art_tax_software.md`
  - `03_source_material.md`
  - `04_legal_liability.md`
  - `05_tooling_language.md`
  - `06_architecture.md`
  - `07_text_extraction_prior_art.md` (added after the build: what another extraction pipeline offers this project; source of T-022 to T-024)
- Synthesis: `research/report.md`
- Spec documents: `spec/spec.md`, `spec/design.md`
- Form and worksheet definitions: `forms/<year>/<form>.yaml`; line ids are `<form>.<name>` and survive renumbering (the printed number is a field)
- Parameters and registers: one file per tax year (`params/<year>.yaml`, `ambiguities/<year>.yaml`)
- Citation locators: `p. N, <heading>, "<quote>"`, segments separated by `;`, a segment naming another document first (`i4562 p. 4, Part I`); the heading is the first phrase after the pages and must be printed text, quotes verbatim with `...` for an omission (checked by `tools/citations.py`). On a computed line (atom not `input`, `param` or `copy`) every segment must carry pages, a quote, or one printed line number of a form document (`Schedule 8812 (2025), line 10`, verified beside the label's words in the form's text); a span (`lines 1–18`), a list of lines or the document's title alone is listed under "Locators to rewrite" in `reports/<year>/citations.md` (fails with `--strict`, which check-all passes)
- Tables: `tables/<year>/<table>.yaml`; generated tables record their extractor and source hash in a header comment
- Adopting a year: archive its sources (`tools/sources-<year>.json`, `fetch_sources.py --year <year> --fetch`), run `tools/year_diff.py --from <old> --to <new> --adopt`, work through the report (including the definitions that still name the old year) and the new year's citation check until it builds, run `tools/fixtures_year.py --from <old> --to <new>`, then add the year to `years.json`. Drafts are catalogued with `"draft": true` and never adopted; while a year's definitions cannot build (a cited document has no edition yet), `tools/fixtures_year.py --plan` reports what would be re-recorded without writing fixtures
- Boundary fixtures: an input on a parameter's boundary is written relative to it (`{"param": "medicare.threshold", "status": "mfj", "offset": -1}`), not as the year's amount
- The tax year: every engine command, tool, `check_all.sh` and the Lean `taxeval` take `--year N`; without it they use the newest year listed in `years.json` (`adopted`), so a year under preparation becomes the default only when it is added there. The engine resolves it in `engine/src/year.ts`, the tools in `tools/taxyear.py`; both remove the flag before a command parses its own arguments

## Constraints on contents

- No personal tax documents or figures taken from them are stored in this repository. Fixtures are synthetic or drawn from official IRS worked examples.
- Money is integer cents; rates are integer pairs; rounding only through cited steps.
- Nothing below the data layer contains tax rules: every value is an atom application with a citation, and the build fails if a check fails.
